# Maintaining this archive

For an explicit checkpoint request, update `LeoWilder01/build-in-public` through the GitHub connector when available:

1. Read the latest version of this file, [record format](docs/record-format.md), the project list linked there, and relevant existing records. Use the current conversation, inspected artifacts, test results, or explicit user reports as evidence; never imply access to unseen context.
2. Select normally zero to two new, independently useful claims. Each must capture exactly one concept or one event, normally in one or two concise sentences. Split independent claims; for a routine checkpoint select the most meaningful ones rather than expanding into a session summary. No activity lists, plans, filler, session summaries, or invented progress. Preserve scope and uncertainty; distinguish reported results from verified ones.
3. Deduplicate against the archive, then append using the format guide. Write a concise record title and equivalent English and Chinese versions and locate each entry in the shared context hierarchy; reuse the current discussion scope until its larger purpose changes. Preserve existing entries and order. Write nothing when there is no meaningful new information. Include useful public evidence links in both language versions, and exclude private or sensitive information.
4. Review the diff against the format guide’s concrete-wording rule; validate bilingual text, allowed projects, context references and hierarchy, and YAML. Commit directly to the archive and report the file and commit. If the remote branch changed, reread and merge without overwriting others' work or force-pushing.

Correct factual errors in place; record later changes separately so historical decisions remain visible. Do not seed fictional or administrative entries merely to fill the archive. Never create a second archive in another project.

For repository maintenance, keep documentation responsibilities separate: README explains purpose and website setup; this file defines agent behavior; the format guide alone defines storage and metadata. Preserve unrelated changes and verify website behavior when changing it.
